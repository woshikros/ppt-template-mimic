# 方法融合与适配决策

来源分工：Opus 提炼的参考 PPT 复刻方法用于视觉观察、内容规划、风格清单和逐页复验；pptx-automizer 用于导入原稿、复制原页、修改原生对象以及保留关联资源。运行代码不依赖 WorkBuddy、Codex 或某个专属 Skill 环境。

| 情况 | 采用方式 | 验收重点 |
|---|---|---|
| 原稿有相近页面结构 | 复制原页、改文字/表格 | 继承样式、Logo、画幅与完整性 |
| 原页中有复杂组合图 | 保留组合结构，按对象 id 修改 | 组合坐标、连接线、图标和文字布局 |
| 表格仅内容或行数变化 | 原生表格适配 | 单元格内容、行列、颜色语义、可编辑性 |
| 内容结构与原图不同 | 按参考样式编写专门适配 | 逻辑关系正确，不为保形而扭曲内容 |
| 动画、音视频、特殊效果影响使用 | 用已有原生 PowerPoint 能力评估适配 | 实际播放、资源链接，不能仅看静态截图 |

保留的 Opus 经验：

- 标题编号、句式、繁简体、中英混排及信息密度，也是模板风格的一部分。
- Logo 可位于 slideLayout，封面图可作为背景，不要只查当前页图片。
- 改整段 `text_frame.text` 会破坏富文本；这里保留原段首个 run 的格式，再写新文本。复杂富文本需专门适配。
- 中文字体必须兼顾 Latin 与 EA；语言标记须跟随内容语言，而不是机械按英文校对。
- 单字掉到下一行、长标题压住 Logo、表格切掉文字等，只能通过实际渲染可靠发现。

调整的原方法：

- 不固定“五页 Demo”；用户页数优先，未指定页数才默认三页。
- 不先造新图再努力贴近模板；先查是否已有可直接复用的原页/原组合。
- 不依赖私有 python-pptx 接口删除页或跨包 deepcopy；跨文件形状还依赖关系、素材和主题。导入由 pptx-automizer 完成。
- 不照抄特定模板的蓝/绿配色、12pt/15pt 字号或某个 BLOCK_ARC 调整系数；这些来自单一示例，跨库角度单位和调整语义还可能不同。
- 环形分类、层级架构、阶梯步骤、左右对比是可识别的图形套路，不是固定主题。保留原稿颜色、间距、边框、图形逻辑；需要新建时以原生可编辑图形实现，不整页截图。
- 不强制使用不存在的发送工具。发现当前 WorkBuddy 可用的文件交付入口再发送。

本包在两类实际参考稿上做回归：蓝色中文组合图模板、橙白品牌原生表格模板。公司文件仅用作本地测试，不随包分发。这证明所测路径可用，不能保证任意动画、媒体、SmartArt 或合并表格均被完整保留。
